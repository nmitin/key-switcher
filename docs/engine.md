# Движок коррекции

Документ описывает `layoutpilot-core::Engine` — платформенно-независимый слой,
который решает, когда и что исправлять. Он не читает ввод и не инжектит
события; это делают бэкенды, а движок получает уже нормализованные символы.

## Поток данных

```
capture → normalize → Engine::on_char(ch, InputContext) → Option<Action>
                                                          │
                                      CorrectionManager / Injector
```

`InputContext` — снимок окружения на событие:

- `profile` — уже разрешённый профиль приложения;
- `active_layout` — текущая раскладка (`us`/`ru`);
- `layout_trusted` — достоверность layout state (FR-39);
- `ime_active` — активен ли композитор (FR-08);
- `modifiers` — Ctrl/Alt/Shift/Super;
- `app_id` — для детектора и диагностики.

## Состояния

| Состояние | Условие | Что возможно |
|---|---|---|
| `Idle` | буфер пуст, undo нет | ввод |
| `Typing` | есть незавершённое слово | ввод, `fix_last_word` |
| `Corrected` | есть undo-запись, слово завершено | undo/redo до следующего ввода |

Сброс (`reset`) очищает буфер, незавершённое слово и undo. Причины:
`FocusChange`, `PointerActivity`, `ScreenLock`, `LayoutChange`,
`DeviceChange`, `IdleTimeout`, `Pause`, `Disabled`, `Shortcut`, `Manual`
(FR-40).

## Триггеры

Срабатывание — на пробел и пунктуацию:

- `. , ! ? ; : ) ] } "`.

Есть важное уточнение (ADR-017): если пунктуация на той же физической клавише
является буквой в другой раскладке, она остаётся **внутри** слова. Например,
`cfk.n` — это `салют` (`.` = `ю`), `cvt[` — `смех` (`[` = `х`). Хвостовая
пунктуация отделяется и сохраняется: `ghbdtn. ` → `привет.`. Поэтому для
таких символов коррекция происходит на следующем разделителе (пробеле), а не
сразу.

`!`, `?`, `)` и прочая не-буквенная пунктуация срабатывает сразу. Слова,
оканчивающиеся на букву-пунктуацию (`ю`, `б`, `ж`, `э`), пока не исправляются:
хвостовой символ трактуется как разделитель. Enter не является триггером
(ADR-001). Tab — только в профиле `aggressive` и только при
`tab_trigger_in_aggressive = true`. Апостроф считается символом слова, а не
триггером: `don't` остаётся одним словом.

## Профили

| Профиль | Авто | Мин. длина | Порог |
|---|---|---|---|
| `auto` | да | 3 | 0.97 |
| `aggressive` | да | 2 | 0.90 |
| `conservative` | да | 4 | 0.995 |
| `manual` | нет | — | — |
| `off` | нет, буфер не ведётся | — | — |

`ProfileResolver` применяет правила в порядке: точный `app_id` → glob по
убыванию специфичности → `*` → default. Сравнение `app_id` — ASCII
case-insensitive.

## Защитные правила

До вызова детектора движок отказывается от коррекции, если:

- слово короче минимальной длины профиля;
- слово помечено как «прилипшее» к цифрам (`abc123`, `123abc`);
- токен похож на URL, email, путь, версию, идентификатор или shell-флаг
  (`https://…`, `user@example.com`, `/usr/bin`, `v1.2`, `some_id`, `--flag`);
- зажаты Ctrl/Alt/Super;
- layout state недостоверен;
- активен IME (ручной режим при этом работает);
- профиль `manual` или `off`.

Правила намеренно консервативны: не исправить URL дешевле, чем испортить его.

## Детектор

```rust
pub trait Detector {
    fn confidence(&self, context: &DetectionContext<'_>) -> f32;
}
```

Возвращает калиброванную `P(кандидат — то, что имел в виду пользователь)`.
Движок сравнивает её с порогом профиля.

Production-реализация — `layoutpilot_dict::DictionaryDetector`:

- FST-словари ru/en по 50k слов;
- char-биграммы с маркерами границ;
- `score = dict_weight · log P_dict + ngram_weight · avg(log P_bigram)`
  + пользовательская частота;
- `p = sigmoid((score(candidate) − score(typed) − known_bias) / temperature)`;
- если кандидата нет в словаре, `p = 0`.

`LexiconDetector` остаётся в ядре как простой детектор для unit-тестов.
Подробности и замеры — [`docs/dictionaries.md`](dictionaries.md).

## Менеджер коррекции

`CorrectionManager` владеет движком и превращает `Action` в
`CorrectionPlan`:

```text
CorrectionPlan {
    kind:       Replace | Undo | Redo,
    layout:     куда переключиться,
    backspaces: сколько раз нажать Backspace (слово + разделитель),
    text:       что напечатать (только замена),
    separator:  разделитель, который печатается отдельно после паузы,
}
```

Для `Replace` источник — текущая раскладка, цель — `source.other()`. Для
`Undo`/`Redo` направление берётся из последней коррекции. `is_typeable()`
проверяет, что каждый символ плана есть на клавишах целевой раскладки; это
делается до удаления текста, чтобы не оставить полуисправленное состояние.

## Действия и undo

`Action::Replace(Correction)` содержит:

- `original`, `converted`;
- `separator` — чем было завершено слово;
- `word_chars` — сколько символов удалять.

Разделитель входит в число Backspace и печатается отдельным шагом после
короткой паузы. Это исправляет и оставшуюся первую букву, и пропадавший
последний пробел (ADR-018). `delete_chars`/`insert_text` остаются
низкоуровневыми помощниками; план использует `word_chars` и `separator`.
После коррекции буфер движка обновляется на `converted`, чтобы контекст
следующих слов был корректным.

Undo доступен, пока после коррекции не было ввода, смены фокуса, раскладки
или другого сброса. Повторное нажатие после undo возвращает коррекцию
(`Action::Redo`). Любой новый символ инвалидирует запись.
