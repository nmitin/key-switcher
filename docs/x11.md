# X11-бэкенды

Крейт `layoutpilot-x11` — первый платформенный срез. Он не содержит политики:
движок и словари остаются в `layoutpilot-core` / `layoutpilot-dict`, а здесь
только X11-примитивы.

## Что реализовано

| Компонент | Назначение |
|---|---|
| `X11Injector` | XTest: tap keycode, Shift, Backspace, текст по таблице раскладки |
| `X11LayoutState` | XKB: текущая группа, активная раскладка, переключение группы |
| `XRecordCapture` | глобальный захват KeyPress/KeyRelease через RECORD |
| `X11Focus` | `_NET_ACTIVE_WINDOW`, `WM_CLASS`, заголовок |
| `X11HotkeyGrabber` | `XGrabKey` с вариантами Lock/NumLock, чтение grabbed-событий |
| `char_for` | keycode + Shift/CapsLock → символ через таблицы ru/en |

XTest использует XKB keycode (тот же, что в `Keystroke::keycode`), а не evdev.
`tap_text` сначала проверяет все символы, и только потом отправляет запросы,
чтобы не оставить частично введённую строку.

`XRecordCapture` следует штатной схеме XRecord: одно соединение управляет
контекстом, второе читает блокирующий поток данных в отдельном потоке.
Конструктор ждёт `START_OF_DATA`, поэтому после `new()` захват уже активен.
`stop()` выключает контекст и джойнит поток; `Drop` делает то же самое.

## Пример

```rust
use layoutpilot_core::LayoutId;
use layoutpilot_x11::{char_for, X11Injector, X11LayoutState, XRecordCapture};

let mut capture = XRecordCapture::new()?;
let mut injector = X11Injector::new()?;
let layouts = X11LayoutState::new(vec![LayoutId::Us, LayoutId::Ru])?;

let layout = layouts.active_layout()?.unwrap_or(LayoutId::Us);
for event in [capture.recv()?, capture.recv()?] {
    if let Some(ch) = char_for(&event, layout.table()) {
        println!("{ch:?}");
    }
}
injector.tap_backspace(1)?;
layouts.switch_to(LayoutId::Ru)?;
injector.tap_text("привет", LayoutId::Ru.table())?;
```

## Проверка вживую

Юнит-тесты нормализации идут в обычном `cargo test`. Два интеграционных теста
помечены `#[ignore]`, потому что им нужен X-сервер:

```sh
DISPLAY=:1 cargo test -p layoutpilot-x11 -- --ignored --test-threads=1
```

- `capture::records_an_xtest_key` нажимает только Shift через XTest и проверяет,
  что XRecord его поймал. Текст в приложение не вводится.
- `layout::reads_and_restores_the_group` переключает XKB-группу на другую и
  возвращает исходную.

Оба теста проверены на XWayland (`DISPLAY=:1`), где доступны XTEST 2.2 и
RECORD 1.13.

## Ограничения

- Это X11/XWayland-путь. Wayland-приложения вне XWayland не видны XRecord.
- Layout state сейчас опрашивается по требованию; событийный `XkbStateNotify`
  — следующий шаг этапа 0.
- Группы ограничены четырьмя (`XkbGroup1..4`).
- Shift keycode зафиксирован как 50 (стандартная evdev-раскладка).
- `X11Injector` ведёт журнал отправленных событий (`sent_events`,
  `take_sent_events`), а демон использует его для подавления собственных
  XTest-событий (FR-09). Сам по себе примитив события не фильтрует.
- Нет per-window раскладки и восстановления фокуса.
