# Этап 0. Спайки: чек-лист и программа проверки

**Проект:** LayoutPilot (рабочее название)
**Основание:** ТЗ v0.2, §17 (этап 0), §8 (бэкенды), §9.5 (инъекция), NFR-01…NFR-15
**Статус:** готов к выполнению, 2026-10-31
**Длительность:** 2–3 недели (15 рабочих дней)
**Результат этапа:** отчёт с матрицей возможностей и зафиксированные решения по бэкендам
(ADR в `docs/decisions.md`), обновлённое ТЗ при необходимости.

---

## 1. Зачем этот этап

Этап 0 снижает четыре главных риска проекта, которые нельзя закрыть рассуждением:

1. **Wayland-фрагментация.** EIS, virtual-keyboard-v1 и нативные API раскладки ведут себя
   по-разному в GNOME, KDE, Sway и Hyprland. Нужны факты, а не документация.
2. **Недостоверный layout state.** Ошибка в активной группе означает порчу чужого текста —
   самый дорогой баг утилиты. Проверяем событийность и per-device поведение.
3. **Инъекция.** Приём «Backspace × N + те же физические клавиши» должен работать в GTK,
   Qt, Electron и терминале через каждый инжектор.
4. **Бюджеты.** p99 ≤ 15 мс, RSS ≤ 60 МБ, старт ≤ 300 мс — проверяются на реальном железе
   до того, как архитектура затвердеет.

**Не цель этапа:** production-код, красивый CLI, словари, алгоритм скоринга, GUI.
Спайки — выбрасываемый код в `spikes/`, который не попадает в `main`.

---

## 2. Правила проведения

- **Один спайк — один вопрос.** Если появляется второй, он выносится в отдельный пункт.
- **Таймбокс.** Не более указанного в карточке. Таймбокс истёк — фиксируем результат
  «не выяснено» и решение о fallback, а не продлеваем до бесконечности.
- **Всё измеряем на целевом окружении.** «У меня работает» без версий дистрибутива,
  композитора и ядра — не результат.
- **Никаких необратимых действий на рабочей машине.** EIS, uinput и правки keymap —
  только в VM со снапшотом. В хосте — максимум read-only evdev.
- **Сырые нажатия не логируем на диск.** Только синтетический ввод и агрегированные метрики;
  это же правило проверяем в спайке приватности.
- **Каждый спайк заканчивается записью:** гипотеза → что сделали → цифры → вывод →
  решение (GO / NO-GO / FALLBACK).
- **Спайк-код живёт в `spikes/<id>/`** и удаляется или архивируется после этапа.

## 3. Стенд и матрица окружений

### 3.1 Обязательные окружения

| ID | Окружение | Сессия | Зачем |
|---|---|---|---|
| T1 | Ubuntu 24.04 LTS | X11 | XRecord/XTest, XKB state, per-window |

### 3.2 Референсное железо

Нужны две конфигурации, иначе бюджеты NFR-01/03/05 не проверить:

- **R1 (современная):** 8+ ядер, 16 ГБ, NVMe, ядро 6.8+.
- **R2 (старая):** 2–4 ядра, 4–8 ГБ, SATA SSD, ядро 6.1–6.6. Именно на ней проверяются
  p99, RSS и старт.

### 3.3 Тестовые приложения (одни и те же во всех окружениях)

GTK4 (`gnome-text-editor` / `gtk4-demo`), Qt6 (`kate` / `qcalc`), Electron (VS Code или
Slack), терминал (konsole/gnome-terminal/foot), браузер (Firefox). Отдельно — поле пароля
и окно с явным blacklist.

### 3.4 Права и доступы

- пользователь в группе `input` — read-only evdev;
- udev-правило на `/dev/uinput` (только для спайка uinput-фолбэка);
- портал `org.freedesktop.portal.RemoteDesktop` — согласие на сессию;
- AT-SPI включён (`gsettings get org.gnome.desktop.interface toolkit-accessibility`);
- для X11 — доступ к `$DISPLAY`, `xhost` не расширяем.

## 5. Карточки спайков

### S0-01. evdev: захват и права

**Гипотеза.** Read-only evdev покрывает все клавиатуры, переживает hotplug и не требует root.

**Проверяем.**
- список устройств: `ls -l /dev/input/by-id/`, `cat /proc/bus/input/devices`;
- права: `groups`, `namei -l /dev/input/event*`, поведение без группы `input`;
- чтение: минимальный Rust-спайк на `evdev` (или `evtest`) — keycode, value, timestamp, device;
- несколько клавиатур одновременно (встроенная + USB + BT);
- hotplug: отключение/подключение во время набора;
- потеря событий: генератор 10 тыс. слов/мин (скрипт на `ydotool`/uinput), сверка счётчиков;
- засыпание/пробуждение, отзыв прав на лету (`chmod`), реакция на `ENODEV`.

**Метрики.** потерянные события (шт.), задержка чтения p50/p99, CPU в простое, поведение
при отзыве прав, число требуемых привилегий.

**Pass.** 0 потерь на 10 тыс. слов/мин; нет `EVIOCGRAB`; корректный hotplug; без root
(только группа `input`); при отзыве прав — понятная ошибка, не паника.

**Fail / fallback.** Если evdev недоступен без root в целевом дистрибутиве — проверить ACL
и udev-правило, зафиксировать в онбординге; альтернатива для v1 — XRecord на X11.

**Артефакт.** `spikes/s0-01-evdev/README.md` + сырые логи счётчиков (без текста).

---

### S0-02. X11: захват, инъекция, состояние, фокус

**Гипотеза.** На X11 связка XRecord (capture) + XTest (inject) + XKB state + `_NET_ACTIVE_WINDOW`
закрывает весь сценарий без Wayland-сложностей.

**Проверяем.**
- XRecord: глобальные события, keycode, modifiers, timestamp;
- XTest: `Backspace × N`, переигрывание keycode, хоткей переключения группы;
- активная группа: `XkbStateNotify` (событие) и `XkbGetState` (сверка); смена через
  `xkb-switch`, панель DE, хоткей;
- фокус: `_NET_ACTIVE_WINDOW`, `XGetInputFocus`, `WM_CLASS`, заголовок;
- per-window: запоминание группы для окна и восстановление при возврате фокуса;
- ввод в GTK/Qt/Electron/терминале, включая Caps Lock и Shift;
- цикл: собственные XTest-события не должны попадать в буфер (FR-09).

**Метрики.** задержка «разделитель → инъекция» p50/p99; корректность группы после 100
переключений; верность `WM_CLASS`; ложные срабатывания на собственных событиях.

**Pass.** Сквозной сценарий `ghbdtn` + пробел → «привет» во всех четырёх типах приложений;
undo; per-window; собственные события отфильтрованы; p99 укладывается в бюджет.

**Fail / fallback.** Если XRecord конфликтует с XTest-инъекцией — разделить потоки/клиенты,
проверить таймстемпы; при неустранимом конфликте — evdev-capture + XTest-inject на X11.

**Артефакт.** `spikes/s0-02-x11/README.md`, видео/лог сценария, замеры.

### S0-03. EIS/libei в GNOME и KDE

**Гипотеза.** EIS через портал RemoteDesktop даёт инъекцию в evdev-семантике, пригодную для
«переигрывания» физических клавиш, и умеет Unicode через `ei_text`.

**Проверяем.**
- получение EIS-сессии через `org.freedesktop.portal.RemoteDesktop` (согласие, сохранение
  разрешения между запусками);
- `ei_device` keyboard: отправка keycode, modifiers, `Backspace × N`, пачки;
- `ei_text.utf8`: кириллица, эмодзи, редкая пунктуация;
- приём в GTK/Qt/Electron/терминале; поведение при активном IME;
- переподключение после suspend, logout/login, падения демона;
- конфликт с физическим вводом (порядок событий, дубли);
- задержка установления сессии и инъекции.

**Метрики.** p50/p99 инъекции; время установления сессии; успешность reconnect (N из 10);
число сценариев, где нужен Unicode-путь.

**Pass.** Инъекция и Unicode работают в GNOME 46+ и KDE 6+; после suspend сессия
восстанавливается автоматически или переустанавливается с понятным сообщением; нет дублей.

**Fail / fallback.** Нет EIS в конкретной версии/сборке — фиксируем в матрице, включаем
virtual-keyboard (wlroots) или uinput/clipboard; для GNOME без EIS — clipboard-fallback
для ручного режима.

**Артефакт.** `spikes/s0-03-eis/README.md` + матрица «окружение × операция × результат».

---

### S0-04. virtual-keyboard-v1 в Sway и Hyprland

**Гипотеза.** `zwp_virtual_keyboard_v1` позволяет задать keymap и переигрывать клавиши
без uinput-устройства.

**Проверяем.**
- подключение протокола, создание виртуальной клавиатуры, загрузка keymap (ru/en, обе группы);
- отправка keycode + modifiers, `Backspace × N`, повтор, пачка;
- переключение группы внутри keymap vs нативное переключение композитора;
- per-device: какая группа применяется к виртуальному устройству;
- приём в foot/kitty, GTK, Qt, Electron;
- поведение при перезапуске композитора.

**Pass.** Сценарий коррекции и undo работают в Sway и Hyprland; keymap можно обновлять
без пересоздания; нет «залипания» модификаторов.

**Fail / fallback.** Если keymap нельзя обновить на лету — пересоздание устройства;
если per-device группа не совпадает с физической — uinput-fallback с явной пометкой
в `doctor`, в играх запрещён.

**Артефакт.** `spikes/s0-04-vk/README.md`.

### S0-05. Layout state: события, per-device, достоверность

**Гипотеза.** Для каждого окружения есть событийный источник активной группы; опрос 200 мс —
только fallback, и он помечается недостоверным.

**Проверяем по окружениям.**

| Окружение | Что проверить |
|---|---|
| X11 | `XkbStateNotify`: смена группы хоткеем, панелью, `xkb-switch`; номер группы и keymap |
| KDE | фактический D-Bus-интерфейс (см. S0-07), сигнал смены; если сигнала нет — опрос 200 мс и его латентность |
| GNOME | `gsettings monitor org.gnome.desktop.input-sources current`, смена через панель и CLI |
| Sway | события `input`/`xkb_layout`, смена через `swaymsg`, несколько клавиатур |
| Hyprland | событие `activelayout` на event socket, смена через `hyprctl`, несколько клавиатур |

**Сценарии.** 1000 переключений в каждом окружении; смена группы во время набора; две
клавиатуры с разными группами; отключение устройства; перезапуск композитора; смена
раскладки из другого приложения.

**Метрики.** ошибки состояния (шт.), задержка «смена → событие» p50/p99, доля переключений,
пойманных опросом, поведение при неизвестном устройстве.

**Pass.** 0 ошибок нормализации на матрице; событийный путь < 50 мс; при неизвестном
устройстве/провайдере состояние помечается недостоверным и авто-путь выключается (FR-39).

**Fail / fallback.** Только опрос — фиксируем как «недостоверно»; авто-коррекция в этом
окружении выключается по умолчанию, ручной режим остаётся.

**Артефакт.** `spikes/s0-05-layoutstate/README.md` + таблица результатов по T1–T5.

### S0-06. Фокус и `app_id`

**Гипотеза.** `app_id` достаточно надёжен для blacklist и профилей; в GNOME AT-SPI даёт
best-effort без расширения Shell.

**Проверяем.**
- X11: `_NET_ACTIVE_WINDOW`, `XGetInputFocus`, `WM_CLASS`, заголовок, смена фокуса;
- KDE: KWin D-Bus/scripting — `app_id`, заголовок, активное окно;
- Sway: `swaymsg -t get_tree` и события `window::focus`;
- Hyprland: `hyprctl activewindow -j` и событие `activewindow`;
- GNOME: AT-SPI (`org.a11y.atspi`) — имя приложения, роль, задержка; поведение при
  выключенной accessibility;
- приложения: GTK, Qt, Electron, терминал, браузер, диалог пароля;
- смена фокуса мышью, Alt+Tab, закрытие окна, полноэкранный режим.

**Метрики.** точность `app_id` (≥ 95% на наборе), задержка получения p50/p99, доля
«неизвестно», влияние AT-SPI на CPU.

**Pass.** Для X11/KDE/Sway/Hyprland `app_id` стабилен; в GNOME — best-effort, при
неизвестном приложении консервативный режим и запись в диагностику (FR-41).

**Fail / fallback.** AT-SPI слишком медленный/нестабильный — в GNOME v1 blacklist только
по глобальному списку приложений, per-window не заявляем; extension — v1.x.

**Артефакт.** `spikes/s0-06-focus/README.md`.

### S0-07. API переключения раскладки

**Гипотеза.** Нативные API позволяют переключать группу идемпотентно и без побочных эффектов.

**Проверяем.**
- X11: `XkbLockGroup`, сверка с `XkbGetState`, отсутствие «дребезга»;
- KDE: найти фактический сервис/путь/интерфейс (`busctl --user list`, `busctl --user introspect`,
  `qdbus`), методы чтения/установки, сигнал; поведение per-window;
- GNOME: `gsettings` `current`/`sources`, смена индекса, границы, отсутствие per-window;
- Sway: `swaymsg input <id> xkb_switch_layout next|prev|<n>`, per-device;
- Hyprland: `hyprctl switchxkblayout <device> next|prev|<id>`, per-device;
- внешняя смена (панель, хоткей) видна провайдеру состояния;
- идемпотентность: повторный вызов не меняет группу;
- отсутствие зацикливания «наш вызов → событие → снова вызов».

**Pass.** Переключение работает во всех T1–T5; повторный вызов идемпотентен; внешние
смены видны; в GNOME per-window явно не поддерживается и это отражено в `doctor`.

**Fail / fallback.** Нет API — эмуляция хоткея через инжектор, с риском зависимости от
пользовательской комбинации; фиксируем как ограничение.

**Артефакт.** `spikes/s0-07-switch/README.md` + точные D-Bus/CLI-команды и версии.

### S0-08. Клавиатурная обратимость ru↔en

**Гипотеза.** XKB keymap даёт однозначное соответствие «символ ↔ (keycode, modifiers)»
для русского и английского; всё остальное детектируется как необратимое.

**Проверяем.**
- построение таблицы символов для `us`, `ru` (все уровни: Shift, AltGr, Caps Lock);
- инволютивность `convert(convert(x)) == x` на корпусе 1000 слов;
- регистр, пунктуация, цифры, дефис, апостроф;
- символы вне клавиатуры (эмодзи, редкая пунктуация, `№`, `—`) — детект необратимости;
- мёртвые клавиши и компоузинг;
- слова, валидные в обоих языках (`at`, `no`, `on`, `to`) — не исправлять без перевеса;
- Caps Lock и Shift: `Ghbdtn` → `Привет`.

**Pass.** Инволютивность 100%; 0 «полуисправленных» строк; необратимые строки в авто-режиме
не трогаются; таблицы воспроизводимы генератором.

**Fail / fallback.** Если XKB-таблица неполна для целевой раскладки — расширяем генератор
из `xkb-data`, фиксируем версию; спорные символы — только ручной режим.

**Артефакт.** `spikes/s0-08-xkb/README.md`, генератор таблиц, корпус.

### S0-09. Задержка, память, старт

**Гипотеза.** Бюджеты NFR-01/03/05 достижимы на R2 с запасом.

**Проверяем.**
- замер «нажатие разделителя → событие инъекции» на R1 и R2, p50/p99, 10 тыс. слов;
- разложение по стадиям: evdev/XRecord → нормализация → скоринг → инъекция;
- RSS демона: idle, после 10 тыс. слов, с загруженным словарём (mmap), без ONNX;
- старт до готовности: cold/warm, 20 запусков;
- CPU в простое и при наборе;
- поведение при 100% загрузке CPU (фоновый `stress-ng`).

**Pass.** p99 ≤ 15 мс на R2; RSS ≤ 60 МБ; старт ≤ 300 мс; CPU idle ≤ 0.5%; нет роста RSS
после 10 тыс. слов.

**Fail / fallback.** Если бюджет не достигается — фиксируем узкое место и пересматриваем
NFR (ADR), а не «оптимизируем потом»; рассматриваем `tract` vs `ort`.

**Артефакт.** `spikes/s0-09-perf/README.md` + CSV замеров + графики.

### S0-10. IME: fcitx5/ibus

**Гипотеза.** Факт активности IME определяется надёжно, авто-коррекция при компоузинге
выключается, ручной режим не ломает preedit.

**Проверяем.**
- `fcitx5-remote`, `ibus engine`, D-Bus-статус;
- ввод CJK и русского через IME в GTK/Qt;
- evdev-события при активном IME: виден ли preedit (ожидаемо — нет);
- поведение при переключении IME на лету;
- ручная коррекция выделенного текста при активном IME.

**Pass.** Авто-режим выключается по умолчанию при активном IME; ручной режим работает
или явно отказывает с понятным сообщением; нет порчи preedit.

**Fail / fallback.** Детект ненадёжен — авто-режим выключается при любом запущенном IME
(консервативно), это документируется.

**Артефакт.** `spikes/s0-10-ime/README.md`.

---

### S0-11. Онбординг, права, systemd, упаковка

**Гипотеза.** Пользователь без root может установить и запустить демон за ≤ 10 минут,
а `doctor` объясняет, чего не хватает.

**Проверяем.**
- установка deb/AUR-прототипа без root (или с одним `sudo` на установку пакета);
- добавление в группу `input`, перелогин, ACL-альтернатива;
- udev-правило для uinput — только опционально;
- systemd user unit с `NoNewPrivileges=yes`, `ProtectSystem=strict`, `PrivateTmp=yes` —
  не ломает ли доступ к `/dev/input`, D-Bus и порталу;
- `doctor`: активный capture/inject/layout state/focus, достоверность, права, версии;
- удаление пакета не оставляет мусора;
- Flatpak: зафиксировать, что evdev/uinput недоступны, и не обещать поддержку.

**Pass.** Сценарий установки воспроизводится на чистой T1/T2/T3; `doctor` даёт конкретное
действие при каждой проблеме; hardening не мешает работе.

**Fail / fallback.** Если systemd-hardening несовместим с порталом/EIS — ослабляем
конкретную директиву и документируем почему.

**Артефакт.** `spikes/s0-11-onboarding/README.md`, черновик `doctor`, unit-файл.

## 7. Решения, которые должны быть приняты

| ID | Решение | Варианты | Критерий выбора |
|---|---|---|---|
| D1 | Основной инжектор Wayland | EIS / virtual-keyboard / uinput / clipboard | покрытие T2–T5, задержка, отсутствие per-device сюрпризов |
| D2 | Источник layout state по окружениям | событие / опрос 200 мс / оба | 0 ошибок; опрос только как недостоверный fallback |
| D3 | Интерфейс KDE | D-Bus сервис X / скриптинг KWin / эмуляция хоткея | стабильность между 6.0 и 6.x, наличие сигнала |
| D4 | Фокус в GNOME | AT-SPI / глобальный blacklist / extension в v1.x | точность ≥ 95% или консервативный режим |
| D5 | Capture на X11 | XRecord / evdev | отсутствие двойного учёта, фокус, задержка |
| D6 | Минимальные версии | версии из T1–T5 / более старые из T6 | что реально проверено; ниже — не заявляем |
| D7 | Бюджеты | подтверждены / скорректированы | замеры на R2 |
| D8 | uinput | fallback / не использовать в v1 | риск античитов и per-device раскладки |

Каждое решение оформляется как ADR-017… в `docs/decisions.md` с ссылкой на спайк и
конкретными версиями окружений.

## 8. Критерии выхода из этапа 0

Этап считается завершённым, когда:

- [ ] Матрица возможностей заполнена для T1–T5 (минимум T1–T4).
- [ ] По каждому спайку S0-01…S0-11 есть карточка с результатом и вердиктом.
- [ ] Приняты решения D1–D8, оформлены ADR с доказательствами.
- [ ] Замеры p50/p99, RSS и старта воспроизводимы на R1 и R2 (CSV + методика).
- [ ] Определены fallback-пути для каждого окружения и они проверены хотя бы частично.
- [ ] Обновлено ТЗ (v0.3), если факты противоречат §8/§17; changelog заполнен.
- [ ] Сформирован backlog этапа 1 с оценками, учитывающий результаты спайков.
- [ ] Нет открытого блокера, который делает MVP невозможным.

**Стоп-условие.** Если EIS и virtual-keyboard одновременно недоступны в целевом
KDE/GNOME, а uinput запрещён для игр — пересматриваем обещание «Wayland в v1» и
выносим его в v1.x, а MVP оставляем на X11 + evdev. Это решение принимается на этапе 0,
а не в середине этапа 2.

## 11. Риски этапа 0

| Риск | Мера |
|---|---|
| Спайки «расползаются» и превращаются в продукт | таймбокс, `spikes/` не мержится, один вопрос на спайк |
| Разные версии в VM и у пользователей | фиксируем точные версии, T6 для дрейфа |
| EIS требует интерактивного согласия на каждый запуск | проверить persistence портала, иначе UX-блокер |
| AT-SPI медленный и нестабильный | замер, порог, консервативный режим |
| Измерения на виртуалке нерепрезентативны | R1/R2 — физическое железо, VM только для API |
| Спайк-код случайно попадает в `main` | отдельная ветка/каталог, ревью перед этапом 1 |
| Приватность: в логи попадают нажатия | только синтетика, агрегаты, проверка логов |
