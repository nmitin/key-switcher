# Конфигурация

Файл: `~/.config/layoutpilot/config.toml` (или `$XDG_CONFIG_HOME/layoutpilot/config.toml`).
Демон читает его при старте; `--config PATH` переопределяет путь. Если файла нет —
используются встроенные значения. Неизвестные поля игнорируются, некорректные
значения отвергаются с понятной ошибкой.

Пример: [`config.example.toml`](../config.example.toml).

## Основные секции

| Секция | Что задаёт |
|---|---|
| `[general]` | включение, языки, триггеры, минимальная длина, порог, хоткеи |
| `[capture]` | `auto`, `evdev`, `xrecord`, `portal`, `ime` |
| `[privacy]` | обучение, таймауты, очистка при смене фокуса, LLM |
| `[inject]` | `auto`, `xtest`, `eis`, `virtual-keyboard`, `uinput`, `clipboard` |
| `[layout]` | backend, per-window, **порядок XKB-групп** |
| `[ime]` | отключение авто при активном IME |
| `[apps]` | профили по `WM_CLASS`/`app_id` |

## Порядок раскладок

```toml
[layout]
order = ["us", "ru"]
```

`order[0]` — `XkbGroup1`, `order[1]` — `XkbGroup2`, и так далее (до четырёх).
Для сессии, где русский стоит первым, используйте `["ru", "us"]`.
Это заменяет прежнюю жёсткую привязку `us` → group 1.

## Триггеры

```toml
triggers = ["space"]               # + "punct", "tab", "enter" при необходимости
backspace_undo = false
```

По умолчанию коррекция запускается только пробелом. Пунктуация остаётся
частью слова и сохраняется, поэтому `руддщ! ` → `hello!` без `HELLO`.
`punct` можно включить явно; пунктуация с зажатым Shift всё равно откладывается
до пробела/Enter.

`tab` — только для `aggressive`. `enter` — opt-in и не рекомендуется (ADR-001):
к отпусканию Enter приложение уже обработало его — сообщение в мессенджере
отправлено, команда в терминале запущена, и исправленное слово попадёт в
следующую строку. Слово перед Enter исправляется двойным Shift. `backspace_undo = true` позволяет отменить
последнюю коррекцию нажатием Backspace; по умолчанию выключено — Backspace
только стирает символ, а отмена делается двойным Shift.

## Профили приложений

```toml
[apps."org.telegram.desktop"]
mode = "aggressive"

[apps."*terminal*"]
mode = "manual"

[apps."*"]
mode = "auto"
```

Порядок: точное имя → glob по убыванию специфичности → `*`.
`*terminal*`, `*konsole*`, `*yakuake*`, `*alacritty*`, `*kitty*` по умолчанию `manual`,
`*keepass*` — `off`.

## Хоткеи

```toml
undo_hotkey = "Pause"
fix_hotkey = "Ctrl+F8"
pause_hotkey = "Ctrl+F9"
double_shift_fix = true
triple_shift_phrase = true
lookback_words = 4
tray = true
early_trigger = false
```

Формат: `Ctrl`/`Control`, `Alt`, `Shift`, `Super`/`Meta` + клавиша.
Клавиша — один печатный символ, `Pause`, `Escape`, `Space`, `Tab`, `Enter`,
`Backspace` или `F1`–`F12`. Пустая строка отключает хоткей. Невалидная строка
отвергается при загрузке конфига.

`double_shift_fix = true` включает ручной фикс двойным Shift: два нажатия
Shift без других клавиш между ними исправляют последнее слово. Это работает
через evdev и не конфликтует с `Ctrl+Shift`. Повторный двойной Shift сразу
после автокоррекции отменяет её. Если слово уже завершено пробелом, двойной
Shift всё равно исправляет его — пробел остаётся на месте.

`triple_shift_phrase = true` добавляет третий Shift: три быстрых нажатия
исправляют всю текущую фразу, включая слова через пробел. Фраза начинается
после последнего знака конца предложения (`. ! ? ; :`), за которым идёт
пробел, или после перевода строки/Tab. Хвостовые пробелы сохраняются.
Ручные жесты и `fix_hotkey` работают и в профиле `manual`; профиль `off`
отключает их полностью.

`lookback_words = 4` — сколько коротких слов перед уверенно исправленным словом
исправить вместе с ним (`f jy yt ghbitk` → `а он не пришел`). `0` выключает.

`tray = true` — иконка в системном трее (StatusNotifierItem: KDE, а также
GNOME с расширением AppIndicator). Щелчок ставит на паузу и снимает с неё;
серая иконка — пауза, зелёная вспышка — только что сработала коррекция.
В подсказке и меню видны счётчик и последнее исправление.

`early_trigger = true` — ранний триггер: слово исправляется посреди набора, как
только его начало (от 4 букв) невозможно в текущем языке и типично для
другого: `ghbd` → `прив`, дальше слово печатается уже в нужной раскладке.
Работает в профилях `auto` и `aggressive`. Если догадка оказалась неверной,
обычная проверка на пробеле вернёт слово обратно. По умолчанию выключен.

Не назначайте хоткеи на сочетания, которыми переключается раскладка. Обычно это
`Ctrl+Shift` или `Alt+Shift`: демон увидит нажатие, но система одновременно
сменит раскладку. Поэтому по умолчанию `fix_hotkey = "Ctrl+F8"`, а
`pause_hotkey = "Ctrl+F9"`.

## Звук и раскладка

```toml
[general]
sound_on_layout_change = true
sound_file = "/usr/share/sounds/freedesktop/stereo/camera-shutter.oga"

[layout]
backend = "auto"       # на KDE автоматически kde-dbus+xkb
order = ["us", "ru"]
```

На KDE демон использует `org.kde.keyboard` для переключения раскладки и
дополнительно синхронизирует XKB-группу для XWayland-инъекции. На остальных
X11-окружениях остаётся XKB group lock.

`sound_on_layout_change` проигрывает звук при смене раскладки — как после
коррекции, так и при ручном переключении. По умолчанию это системный
`camera-shutter.oga`; путь можно заменить на любой OGG/WAV. Используется
`paplay`, затем `pw-play`, затем `canberra-gtk-play`; если все недоступны,
звук отключается с предупреждением.

## Разрешение на инъекцию

```toml
[inject]
request_permission_on_start = true
delete_mode = "backspace"       # backspace | ctrl-backspace
layout_settle_ms = 20
pre_inject_delay_ms = 30
separator_delay_ms = 20
```

`delete_mode = "ctrl-backspace"` удаляет слово одним `Ctrl+Backspace` вместо
подсчёта символов. Это экспериментально: поведение зависит от приложения.
Помогает, когда хвостовой пробел ещё не дошёл до поля, но в некоторых
редакторах удаляет лишнее или оставляет двойной пробел.

`layout_settle_ms` — пауза после смены раскладки перед текстом (для uinput
действует нижняя граница 100 мс); `pre_inject_delay_ms` — пауза перед первым
Backspace, чтобы композитор успел обработать физическое слово (только uinput);
`separator_delay_ms` — пауза перед пробелом/Enter. Backspace выполняется до
переключения раскладки, чтобы не потерять нажатие при перезагрузке keymap. Если Kate/Geany теряют
последний пробел, увеличьте `separator_delay_ms` до 50–100 мс.

На X11 используется XTest. На KDE Wayland первый XTest-ввод может вызвать
запрос «Удалённое управление». Чтобы он не появлялся в момент набора текста,
демон при старте делает один безвредный tap Shift. Это не печатает текст и не
открывает меню, но является настоящим XTest-событием, поэтому KDE показывает
запрос один раз — при запуске.

На Wayland с `inject = "auto"` выбирается uinput, поэтому запрос разрешения не
нужен: `request_permission_on_start` действует только на XTest. Для uinput
нужен доступ на запись к `/dev/uinput`; установите
[`packaging/60-layoutpilot.rules`](../packaging/60-layoutpilot.rules) или
выдайте ACL пользователю активного сеанса.

Если запрос не нужен, поставьте `false`. В `--dry-run` preflight не выполняется:
диагностический режим не должен ничего инжектить. Если разрешение не выдано,
автокоррекция сможет определить слово, но инъекция не сработает.

## Backend'ы

- `capture = "auto"` выбирает `evdev` на Wayland и `xrecord`, если задан
  `DISPLAY` на X11.
- `capture = "evdev"` требует доступ к `/dev/input/event*`; используйте
  udev-правило `uaccess` (рекомендуется) или группу `input`.
- `inject = "auto"` означает `uinput` на Wayland и `XTEST` на X11. Явно можно
  выбрать `uinput` или `xtest`; EIS/virtual-keyboard/clipboard ещё не
  реализованы.
- `layout = "auto"` выбирает KDE D-Bus, Sway IPC или Hyprland IPC по сессии;
  на остальных окружениях — X11 XKB. GNOME-провайдер пока не реализован.

## Валидация

Проверяется:

- `min_word_len` в `1..=64`;
- `confidence_threshold` в `[0, 1]`;
- `privacy.store_keystrokes = false` (в v1 иначе ошибка);
- `layout.order` — 2–4 уникальные раскладки;
- непустые `apps`-паттерны.

## Ограничения

- Hot reload ещё не подключён: изменения применяются после перезапуска.
- `learning`, LLM-поля и хоткеи пока только читаются/валидируются; поведение
  для них появится на следующих этапах.
- `history_size` не создаёт историю: в v1 история не хранится.
- На X11 хоткеи захватываются через `XGrabKey`; при конфликте с другим
  клиентом остаётся пассивный режим, и приложение тоже видит нажатие.
- Startup-разрешение проверено только логикой: живой запуск снова откроет
  системный диалог KDE, поэтому без вашего подтверждения он не запускался.
